# Translations

[English README](../README.md) · [中文 README](../README.zh-CN.md)

## Layout

| File | Purpose |
| --- | --- |
| `locales/en.json` | Complete English catalog and fallback messages |
| `locales/zh-CN.json` | Complete Simplified Chinese catalog |
| `src/i18n.rs` | Embedded catalogs, locale selection, and named placeholders |
| `scripts/check-i18n.py` | Check keys, placeholders, message values, and source references |
| `tests/i18n.rs` | CLI behavior and language-independent machine output |

Both JSON catalogs are compiled into the binary with `include_str!`. There is no network request or working-directory lookup. They are also included in the Cargo source package. No new runtime dependency is needed.

## Choose a language

The global `--lang en` or `--lang zh-CN` flag works before or after a subcommand. Language is selected before command help is built.

Without the flag, the first nonempty value in `LMM_LANG`, `LC_ALL`, `LC_MESSAGES`, and `LANG` is used. Unknown locales, `C`, and `POSIX` use English. Simplified Chinese aliases include `zh`, `zh_CN.UTF-8`, `zh-SG`, and `zh-Hans`. Traditional Chinese has no catalog yet and falls back to English rather than being mislabeled.

The selected language is immutable for the lifetime of the CLI, including its callback thread. Library callers can use `i18n::text(Locale::ZhCn, key)` without changing global state. An uninitialized library defaults to English. Tests use explicit locales or child-process environments, not unsafe process-wide environment mutation.

## Add or edit a message

Use a stable semantic key in both catalogs. Keep complete sentences together; do not build sentences by joining translated fragments.

```json
{
  "output.target": "{software}: installation is unconfirmed."
}
```

```rust
tr("menu.title")
trf!("output.target", software = target.software)
```

Named placeholders can move within a sentence but must have matching names and counts across languages. Do not add formatting specifiers, conversions, or nested templates. Placeholder values are substituted once and are never interpreted as more template text. Escape untrusted paths and server text before passing them to a terminal message, for example with `format!("{:?}", value)`.

`help.template` is a Clap help template, not a `trf!` message. Preserve its upstream placeholders. Command help and help headings are translated; Clap's own parser validation details (such as invalid-option suggestions and built-in default-value annotations) remain in upstream English.

## Keep machine output stable

Translate descriptions, help, notes, blockers, and error messages. Do not translate JSON keys, command names, flags, software/provider IDs, OAuth scope names, outcomes, currencies, numeric values, or timestamps. Preserve original vendor names and imported Magpie data.

The `catalog` JSON response serializes `purpose` as localized prose. Catalog search checks descriptions in both bundled languages, regardless of the selected display language. OAuth errors include a stable `error_code`; do not match errors by their translated text.

A missing translation falls back to English, then to its message key. This prevents a missing message from crashing an operation, but it is not a substitute for validation: complete matching catalogs are required by the checks.

## Check a change

```sh
python3 scripts/check-i18n.py
python3 scripts/test_i18n_checks.py
mise exec -- cargo fmt --all --check
mise exec -- cargo test --locked
mise exec -- cargo clippy --locked --all-targets --all-features -- -D warnings
mise exec -- cargo package --list --locked
```

The package file list must contain both locale catalogs. The Python validator does not compile Rust and is not a replacement for the Cargo checks.

For another language, add a complete JSON catalog, register its `Locale` variant and aliases, include it in `CATALOGS` and `Locale::ALL`, extend the accepted `--lang` values, and add subprocess tests. Update the documentation and packaging checks in the same change.
